# GENIUSBOT-CLIENT requirements

Every requirement this specification owns, with the proof that closes it. Delivery state
and public evidence for each ID are recorded in [`status.json`](status.json); this file
defines what each ID means. The design is in [`spec.md`](spec.md) and [`plan.md`](plan.md),
the test contract in [`test-spec.md`](test-spec.md), and the work order in
[`tasks.md`](tasks.md).

| ID | Requirement | Verification |
|---|---|---|
| `GENIUSBOT-CLIENT-R001.1` | **One backend-adapter import seam.** Every desktop panel and the main cockpit window route all Arbora access through the shared gateway client facade and the single `BackendAdapter` seam; no module imports `agent_utilities`, and agent workflows run on arbora rather than in-process. | A source-tree scan test asserts no module under `geniusbot/` imports `agent_utilities`. |
| `GENIUSBOT-CLIENT-R001` | **Served backend-adapter seam (rollup).** Preserve the original client seam in R001.1 and the bounded dashboard transport and lifecycle in R001.2 and R001.3. | Each child meets its own acceptance; dashboard tests do not prove all panel or release behavior. |
| `GENIUSBOT-CLIENT-R001.2` | **Served dashboard reads.** The adapter reads existing Arbora dashboard layout and data endpoints through GatewayClient. It never imports server configuration or aggregation. It projects received widget fields for cards. It preserves endpoint/TLS/proxy transport behavior, bounded reads, redirect refusal and HTTP failures. Task-scoped pools close on success, failure and cancellation. | tests/test_service_dashboard_transport.py covers exact routes, header preservation, values, redirects, HTTP errors, malformed responses and cancellation cleanup. No live-service or packaging acceptance is implied. |
| `GENIUSBOT-CLIENT-R001.3` | **Nonblocking dashboard lifecycle.** Both layout and values load on QThreadPool. Repeated refresh while busy creates no duplicate worker. Refusal clears old cards; retry can recover. Panel close requests cancellation without blocking. Application quit drains bounded async cleanup without thread termination. Late replies cannot repopulate a closed panel. | tests/test_service_dashboard_async.py exercises the production Qt panel and worker. It covers async reads, refusal, retry, cancellation and a late result. Separate processes test quit with delayed and stalled cleanup. |
| `GENIUSBOT-CLIENT-R002.1` | **Typed registry-entry model and validator.** A typed `OperationRegistryEntry`/`OperationRegistry` model validates operation name, sha256 digest shape, and HTTP method, and `build_registry` refuses a malformed or duplicate entry when the installed generated operation registry is loaded. | Unit tests assert each malformed-entry case (empty operation, bad digest, unsupported method, missing field, duplicate operation, digest mismatch) raises `OperationRegistryError` and a valid registry builds and resolves lookups. |
| `GENIUSBOT-CLIENT-R002.2` | **Operation validated against the installed generated registry at the call site.** Before invoking an Arbora operation, the gateway client wires the `.1` registry model into its pre-call path and rejects an unknown operation or a registry/digest mismatch before any network call, consistent with the ecosystem's shared Arbora operation-client contract. | Unit tests assert an unknown or mismatched operation produces zero network effect and a typed `CLIENT_UNAVAILABLE`-equivalent result. |
| `GENIUSBOT-CLIENT-R002` | **Typed registry-entry model and validator (rollup of 1, 2).** Rollup requirement: delivered by its child rows; LANDED only once every child is. | Every child row is LANDED. |
| `GENIUSBOT-CLIENT-R003` | **Verified credential over TLS, bounded responses.** The gateway client refuses a malformed endpoint, refuses plaintext HTTP to a non-loopback host without explicit opt-in, resolves a TLS profile for the caller's verified credential, and caps every response body against a fixed size limit. | Endpoint-validation and bounded-body unit tests cover unsafe URLs, declared-oversize and streamed-oversize responses. |
| `GENIUSBOT-CLIENT-R004.1` | **Off-thread, non-blocking dispatch.** Every Arbora or backend network call runs on a background thread pool. It reports to the UI only through typed signals. No blocking network or heavy-reasoning call executes on the Qt event-loop thread. | Characterization tests exercise the worker's started/finished/error/progress signal contract. They confirm that the main window stays responsive during a dispatched task. |
| `GENIUSBOT-CLIENT-R004` | **Queued worker signal lifetime and retained behavior (rollup).** R004.1 retains the original obligation. R004.2 owns the bounded lifecycle repair. | Both children meet their own acceptance. The new lifecycle tests do not close the generic obligation. |
| `GENIUSBOT-CLIENT-R004.2` | **Queued worker signal lifetime.** A background runnable keeps its signal object alive until the UI receives completion or failure. Started and progress signals remain available. | tests/test_agent_bridge_worker.py waits for actual queued delivery and retains the success/error exclusivity assertions. |
| `GENIUSBOT-CLIENT-R005.3` | **Retained generic facade failure obligation.** Every gateway facade method that fails (timeout, disconnect, malformed envelope, or an exception from the underlying SDK) returns a typed error/offline result to its caller instead of letting an exception escape into the Qt event loop or reporting a false success. | Unit tests drive timeout, disconnect and exception paths and assert a typed `"result"`/`"error"` payload is returned, never an uncaught exception. |
| `GENIUSBOT-CLIENT-R005` | **Fail-closed, typed errors (rollup).** R005.1 and R005.2 own the bounded graph-client cases. R005.3 retains the complete pre-existing generic facade obligation; those two cases alone cannot close it. | All children meet their own acceptance, including the generic failure paths in R005.3. |
| `GENIUSBOT-CLIENT-R005.1` | **Preserve typed failed graph responses.** An HTTP-error JSON object can have status `failed` and a result object containing `error`. The graph client preserves that nested result. It must not replace this operation failure with gateway-offline text. A non-envelope HTTP error still returns the offline/unavailable result. The backend adapter continues to return its existing failure sentinel instead of treating the failed operation as successful. | The 403 typed-failure and 502 non-envelope tests exercise the production client and adapter. They do not prove every HTTP status or facade method. |
| `GENIUSBOT-CLIENT-R005.2` | **Refuse graph redirects without following.** The graph gateway client must not follow redirects or accept their JSON bodies as success or typed operation failure. It returns the unavailable error for redirect responses, even when the body resembles a success or failed-operation envelope. | `tests/test_graph_query_wiring.py` checks 301, 302, 303, 307 and 308 with both envelope shapes (ten cases), asserting exactly one request to the original graph route. |
| `GENIUSBOT-CLIENT-R006` | **No local approval authority.** A governed or mutating action (an `ActionPolicy` approval, or a tool call behind the authorization dialog) is never authorized by the desktop process itself; the operator's explicit decision is always forwarded to Arbora's server-side approval endpoint, which performs the authoritative check. | Contract tests assert the approval/grant code path issues a request to the gateway's approval endpoint and that no local code path marks an action authorized without that round trip. |
| `GENIUSBOT-CLIENT-R007` | **Embedded terminal sandbox.** The cockpit hosts an interactive terminal (`xterm.js` inside a `QWebEngineView`, bridged over `QWebChannel` to a native PTY/conpty backing process) and starts its backing shell lazily, only on first navigation to the terminal view. | Instantiation tests confirm the terminal widget and its bridge construct correctly, and a view-switch test confirms the shell starts exactly once on first navigation to that view. |
| `GENIUSBOT-CLIENT-R008` | **Lazy, on-demand cockpit panel loading.** Every secondary cockpit view (graph explorer, telemetry, workflow builder, security policy, infrastructure, finance, service dashboard, fleet supervisor, usage/cost, extraction, temporal graph, ask-data, metrics, federated search, voice) is imported and instantiated only on first navigation to that view, shares one background worker, and the sidebar highlights exactly the active view. | A characterization test walks every view index, asserts each panel loads exactly once, the placeholder widget is replaced, and only the active sidebar button is styled active. |
| `GENIUSBOT-CLIENT-R009` | **Honest voice-dictation states.** The voice dictation panel distinguishes no capture device present, a recorder/permission failure, the backend route being unavailable, and a genuine transcription error, and renders each state distinctly rather than collapsing them into one generic message. | Unit tests cover each state (no device, each mapped recorder error, unavailable route, generic failure) and assert a distinct rendered message per case. |
| `GENIUSBOT-CLIENT-R010.1` | **Background tray residency.** A system-tray daemon keeps the cockpit resident with show/terminal/health-check/exit actions, and closing the main window minimizes it to the tray instead of exiting the process while the tray remains active. | Tray action and close-event tests assert each tray action triggers its bound window behavior and that closing the window with an active tray icon hides rather than exits. |
| `GENIUSBOT-CLIENT-R010` | **Console stream lifetime and retained behavior (rollup).** R010.1 retains the original obligation. R010.2 owns the bounded lifecycle repair. | Both children meet their own acceptance. The new lifecycle tests do not close the generic obligation. |

Console cursor movement uses the supported Qt enum. | `GENIUSBOT-CLIENT-R012.1` | **Typed packaging manifest model and validator.** A typed `PackagingManifest`/`PackagingTarget` model and `build_manifest` refuse an incomplete manifest: a missing required target (`console_entry_point`, `onefile_executable`, `windows_installer`, `linux_desktop_entry`), a target missing its build tool or output path, or a target whose version does not match the source tree's declared version. | `GENIUSBOT-CLIENT-R012` | **Typed packaging manifest model and validator (rollup of 1, 2).** Rollup requirement: delivered by its child rows; LANDED only once every child is. | Every child row is LANDED. |
